# deadcite — 引用体检

## 什么时候用

- 用户让你检查一份 AI 生成的报告、行业分析、竞品调研、文献综述的**引用可靠性**
- 用户问「这些引用是真的吗」「数字对得上吗」「参考文献靠谱吗」
- 你自己刚生成长篇报告，需要在交付前自检
- 用户要把报告对外发布，需要一个可复现的把关结论

不适用：判断**论点是否正确**（这是语义问题，不在本工具范围内）。

## 怎么跑

```bash
# 信源自动取报告同目录的 sources/
deadcite report.md

# 指定信源目录或文件，可重复
deadcite report.md -s sources/ -s extra/nbs-2024.csv

# 联网校验链接是否真的能打开
deadcite report.md --fetch

# 机器可读，便于后续处理
deadcite report.md --json
```

没有安装时：

```bash
pip install git+https://github.com/DIUDIU1HAO/deadcite.git
```

## 怎么读结果

退出码：`0` 无问题 / `1` 有问题 / `2` 参数或读取错误。

每条问题带四类标签，**必须区分对待**：

| 标签 | 含义 | 处理方式 |
|---|---|---|
| `参考文献里没有这一条` | 正文引用编号超出参考文献范围 | 确证错误，必须修 |
| `找不到对应信源` / `信源打不开` | 来源不存在或链接失效 | 确证错误，必须修 |
| `数字在原文中不存在` | 报告里的数字在信源全文中找不到 | 确证错误，**最优先处理** |
| `原文中找不到相近表述` | 字面重合度低 | 只算可疑，需人工判断 |

**不要让用户以为「可疑」等于「造假」。** 大幅改写的正确转述也会落到这一类。

## 拿到结果后怎么做

1. **先看 `数字在原文中不存在`**。这类是幻觉里最危险的一种：报告写 1,842 亿、原文写 1,284 亿，结论方向可能完全相反。
2. 对每条确证问题，**回到信源原文核对**，不要直接改数字去迎合工具——工具只能证明「这个数字不在原文里」，不能证明「正确数字是多少」。
3. 引用编号缺失的，要么补参考文献条目，要么删掉该句的引用标记。
4. 可疑项逐条读一遍，判断是「改写幅度大」还是「真的没有依据」。

## 常见误判

- **信源没给全**：只传了报告没传 sources/，所有引用都会变成「找不到对应信源」。先确认信源目录对不对。
- **单位不同**：原文「1,284 百万美元」与报告「12.84 亿美元」对不上，工具会报数字不存在，实际是换算问题。
- **低辨识度数字**：年份、页码、百分比一般不参与比对；如果报了，多半是原文确实没有。
- **Markdown 链接被当引用**：正文里的普通超链接也算引用来源。检查纯文档类 Markdown 时会有噪音，此时建议只用编号引用。

## 汇报给用户时的要求

- 给出**总数与分类计数**（多少条确证、多少条可疑），不要只说「有问题」。
- 列出具体行号与原句，让用户能直接定位。
- 明确说明哪些结论是机械可验证的，哪些只是提示。
- 不要夸大：没跑 `--fetch` 时，链接是否真的能打开是**未知**，不要说成失效。
